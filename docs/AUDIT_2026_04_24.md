# Audit 2026-04-24

## Scope

Audited and changed the host platform, embedded HTTP UI, Python bridge, remote games worker, support bundle export and TTS path.

## Verified Facts

- The project is a C++20/CMake Windows host with an embedded HTTP UI, Python bridge tests integrated into CTest, and a remote games worker under `tools/remote_games_worker`.
- The embedded UI is served from generated assets and validated by `nlp3_panel_http_ui_test`.
- The default CTest preset currently contains 29 tests.
- Full validation passed on 2026-04-24 with `ctest --preset default --output-on-failure` after initializing the Visual Studio build environment with `VsDevCmd.bat`.
- Plain PowerShell in this machine can invoke `cl.exe` without standard MSVC include paths, producing failures on standard headers such as `string_view` and `cassert`.

## Executed Changes

- Hardened local HTTP write actions with Origin validation.
- Added `/api/realtime` to serve fast-changing metrics and recent events without requiring the UI to poll the complete state payload every realtime tick.
- Hardened local Python bridge server hosts and Origin handling for local control and broadcast WebSocket paths.
- Hardened the C++ external WebSocket intake with local Origin validation.
- Removed sensitive default Firebase/admin values from the remote games worker configuration path.
- Added support bundle sanitization for sensitive config and structured logs.
- Fixed TTS chat template handling when `{user}` is present and actor names are enabled.
- Preserved actor flags and corrected boolean coercion in the Python event normalizer.
- Reduced redundant UI work with adaptive polling and cached DOM markup for high-churn UI sections.
